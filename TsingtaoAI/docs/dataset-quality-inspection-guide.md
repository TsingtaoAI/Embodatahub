# TsingtaoAI 数据集质检工作台 — 功能说明

## 概述

数据集质检工作台是 TsingtaoAI 具身智能数据平台的核心模块，提供从**数据导入 → 质量检测 → 人工审查 → 清洗导出**的完整流水线。系统支持 LeRobot、ACT HDF5、robomimic HDF5、UMI Zarr 五种主流机器人数据格式，内置 7 大质量过滤器与 VLM 视觉语言模型辅助评估。

---

## 一、数据导入

### 1.1 支持的格式

| 格式 | 存储形式 | 说明 |
|------|----------|------|
| **LeRobot v2.1 / v3** | 目录树（Parquet + MP4 视频） | HuggingFace LeRobot 社区标准格式 |
| **ACT HDF5** | 单个/多个 `.hdf5` 文件 | ALOHA 等双臂操作数据集 |
| **robomimic HDF5** | 单个 `.hdf5` 文件 | robomimic 框架格式 |
| **UMI Zarr** | `.zarr` 目录或 `.zarr.zip` | UMI 通用操作接口格式 |

### 1.2 导入方式

**方式一：服务器已有路径**
在输入框中输入或选择数据集路径，点击"导入 dataset"。

**方式二：本地上传（类网盘）**
- **拖拽上传**：将文件或文件夹拖到上传区域
- **选择文件**：上传 `.zip` / `.tar.gz` / `.tgz` 压缩包（自动解压），或单个 `.hdf5` / `.h5` 文件
- **选择文件夹**：直接上传整个数据集目录，保留原始目录结构
- 支持上传进度条实时显示
- 上传成功后路径自动填入输入框

**方式三：环境变量配置**
设置 `RDS_SAMPLES_DIR` 环境变量指向数据集根目录，系统自动扫描发现可用数据集并在下拉列表中展示。

## 二、质量检测流水线

### 2.1 流水线架构

```
数据过滤器（7 大阶段）→ Episode 评分器 → 决策分类
                              ↑
                    VLM 视觉语言模型（可选）
```

点击 **"运行清洗 Pipeline"** 按钮即可一键启动。系统通过 SSE（Server-Sent Events）实时推送进度。

### 2.2 评分与决策

每个 Episode 经过所有启用的过滤器检测后，系统根据加权评分自动分类：

| 状态 | 评分区间 | 含义 |
|------|----------|------|
| **通过 (passed)** | score ≥ 0.8 | 质量合格，可直接用于训练 |
| **待审查 (review)** | 0.6 ≤ score < 0.8 | 存在可疑问题，需人工判断 |
| **排除 (excluded)** | score < 0.6 或存在关键缺陷 | 建议从训练集中移除 |

人工可以通过质量面板对自动分类结果进行覆盖（手动标为通过/排除）。

### 2.3 评分权重配置

用户可自定义每个过滤器阶段的权重（0.25× ~ 3.0×），默认权重如下：

| 过滤器阶段 | 默认权重 | 说明 |
|-----------|---------|------|
| 极值检测 | 2.0× | 优先级最高 |
| 运动学一致性 | 2.0× | 优先级最高 |
| 视觉质量 | 1.5× | 高优先级 |
| 突变检测 | 1.5× | 高优先级 |
| 时间同步 | 1.5× | 高优先级 |
| 姿态对齐 | 1.0× | 标准 |
| 元数据完整性 | 1.0× | 标准 |
| VLM 任务成功 | 2.0× | 启用 VLM 时生效 |

## 三、七大质量过滤器

### 3.1 视觉质量（visual_quality）

**检测六类视觉缺陷：**

| 缺陷类型 | 检测方法 | 默认阈值 |
|----------|----------|----------|
| **模糊 (blur)** | 拉普拉斯方差 | < 18.0 |
| **欠曝/过暗 (dark)** | 平均像素值 | < 25.0 |
| **过曝/过亮 (bright)** | 平均像素值 | > 235.0 |
| **低对比度 (low contrast)** | 像素标准差 | < 12.0 |
| **帧冻结 (freeze)** | 帧间 MSE 变化 | < 1.0，连续 ≥ 4 帧 |
| **视频缺失/解码失败** | 文件存在性 + FFmpeg | — |

> 系统使用 FFmpeg 按 2 FPS 采样抽帧，每视频最多 48 帧，支持最多 4 路视频并行解码。检测结果带时间轴可视化和代表性帧证据卡。

### 3.2 突变检测（sudden_change）

检测状态维度和动作维度中的**突变信号**（跳跃、尖峰、瞬变）：

1. 应用中值滤波 + Savitzky-Golay 平滑消除噪声
2. 计算残差（原始值 - 平滑值）、一阶差分（速度）、二阶差分（加速度）、三阶差分（加加速度/jerk）
3. 使用鲁棒统计量（中位数 + MAD，调整因子 8.0×）作为阈值
4. 合并 2 帧内的相邻标记为"事件"
5. 排除夹爪维度（gripper 开合属于正常操作）

> 结果视图展示每个事件的主导指标（delta/加速度/jerk）、严重程度比率和维度信息。

### 3.3 时间同步（state_action_alignment）

检测数据采集中的**时序异常**：

- **时间戳间隙**：帧间隔与预期 `1/fps` 偏差过大
- **时间跨度不匹配**：实际时长与理论时长不一致
- **视频起始偏移**：视频流与数据流时间戳未对齐
- **视频结束偏移**：视频提前或延后结束

### 3.4 极值检测（extreme_value）

检测超出**预期物理范围**的状态/动作值：

- 基于整个数据集的 1% / 99% 分位数计算边界
- 超出 `[q01 - 0.5×IQR, q99 + 0.5×IQR]` 范围的帧被标记
- 夹爪维度自动排除（饱和夹持是正常行为）
- 标记率 ≥ 1% 视为关键缺陷

### 3.5 运动学一致性（kinematic_consistency）

使用 **Pinocchio 正向运动学**验证记录的末端执行器位置是否与关节状态一致：

- 需上传机器人 URDF 模型文件
- 配置关节映射、末端执行器连杆、位置容差
- 自动检测并修正 TCP（工具中心点）偏移
- 位置误差超过容差阈值的帧被标记

> 未配置 URDF 时此阶段自动跳过。

### 3.6 姿态对齐（orientation_alignment）

应用旋转校正矩阵对齐位置与方向数据。当前需要手动设置校正矩阵，默认跳过。

### 3.7 元数据完整性（metadata_completeness）

**六项元数据健康检查：**

| 检查项 | 级别 | 描述 |
|--------|------|------|
| 任务描述 | Episode | 是否存在非空的任务描述文本 |
| 摄像头命名 | 数据集 | 是否使用规范的 `observation.images.*` 前缀 |
| 分辨率一致性 | 数据集 | 各视角分辨率是否声明的且一致 |
| 多视角覆盖 | 数据集 | 是否至少 2 个摄像头视角 |
| 动作字段 | 数据集 | 动作特征维度名称是否完整 |
| Episode 完整性 | Episode | 帧数 > 0，声明的视频文件是否存在 |

## 四、VLM 视觉语言模型评估

### 4.1 功能概述

VLM 通过分析视频帧，利用大模型判断机器人操作任务是否成功完成。这是一个**可选的增强评估层**，能捕捉传统数值检测难以发现的语义问题（如抓取失败、放置偏移等）。

### 4.2 支持的模型

| Provider | 模型示例 | 说明 |
|----------|---------|------|
| **OpenAI 兼容** | `gpt-4o`, `gpt-4o-mini` | 使用 OpenAI API 或兼容端点（支持自定义 Base URL） |
| **Gemini** | `gemini-2.5-flash` | 使用 Google Generative AI SDK |
| **Local** | — | 返回占位结果，用于离线测试 |

### 4.3 配置参数

- **Sample Frames**：每个 Episode 抽取的视频帧数（1–12，默认 4）
- **Prompt**：可自定义评估提示词，`{task}` 占位符自动替换为任务描述
- **API Key**：支持直接填写或从环境变量 `OPENAI_API_KEY` / `GOOGLE_API_KEY` 读取

### 4.4 评估流程

1. 从各摄像头视频中按关键时间点（首帧、末帧、夹爪事件帧）采样
2. 将帧编码为 base64 发送给模型
3. 模型返回 JSON：`{"success": true/false, "score": 0-1, "reason": "..."}`
4. 若 VLM 判定失败，自动将 Episode 从"通过"升级为"待审查"

## 五、Episode 查看与审查

### 5.1 Episode 列表面板

- **搜索/筛选**：按 Episode 编号、任务名称、子任务关键词搜索
- **状态分组**：清洗后自动按"待审查 / 排除 / 通过"分组折叠
- **过滤器切换**：按具体过滤器阶段筛选显示
- **批量勾选**：支持多选用于批量导出
- **每条显示**：分数、状态图标、问题数量（已清洗）或帧数时长（未清洗）

### 5.2 中央查看区

根据当前模式切换显示：

| 模式 | 显示内容 |
|------|---------|
| 无选择 | 空状态提示 |
| 过滤器详情 | 选中阶段的参数、检测结果、证据图/时间轴 |
| Rerun 3D 回放 | 机器人轨迹 3D 可视化 |
| 报告模式 | 完整清洗报告仪表板 |

### 5.3 质量报告面板（右侧）

- Episode 综合得分 + 各属性得分分解
- 质量发现列表（可点击跳转到对应过滤器详情）
- 通过 / 排除决策按钮（人工覆盖自动结果）
- 决策后自动跳转到下一个同状态 Episode 并触发 Rerun 回放

---

## 六、Rerun 3D 可视化

### 6.1 功能

使用 Rerun 框架对单个 Episode 进行**三维回放**，直观展示：

- 机器人末端执行器的 3D 运动轨迹
- 各关节的位置/速度变化
- 夹爪开合状态
- 同步的视频画面

### 6.2 使用方式

1. 在 Episode 列表中选择一个 Episode
2. 点击 **"Replay in Rerun"** 按钮
3. 系统生成 `.rrd` 回放文件并加载 3D 查看器
4. 自动定位到当前 Episode 的时间轴起点

## 七、数据导出

### 7.1 导出格式

| 格式 | 输出类型 |
|------|---------|
| ACT HDF5 | `.hdf5` 文件或目录 |
| robomimic HDF5 | 单个 `.hdf5` 文件 |
| UMI Zarr | `.zarr` 目录或 `.zarr.zip` |
| LeRobot v2.1 | LeRobot v2.1 目录结构 |
| LeRobot v3 | LeRobot v3 目录结构 |

### 7.2 导出范围

支持按状态筛选导出：

- 已选择的 Episode
- 全部已索引
- 当前筛选结果
- 已勾选的 Episode
- 仅通过 / 仅待审查 / 仅排除

### 7.3 导出产物

每次导出生成两个文件：
- **数据集文件**：目标格式的数据
- **conversion_report.json**：包含元数据完整性报告、字段映射关系、后端信息

## 八、清洗报告

### 8.1 报告仪表板

清洗完成后可查看完整的报告仪表板，包含：

- **快照指标**：总 Episode 数、总帧数、总时长、帧率、格式、综合评分
- **质量分布图**：所有 Episode 按分数排序的柱状图，按通过/待审查/排除三色标注
- **夹爪开合曲线**：交互式 SVG 折线图，展示夹爪维度随时间的变化
- **Episode 时长分布**：各 Episode 时长条形图 + 均值参考线

### 8.2 报告下载

点击 **"导出报告"** 按钮可下载完整的 JSON 格式报告，包含：
- 数据集元数据
- 每个 Episode 的评分、状态、各属性得分、发现列表
- 数据契约推断（坐标系、旋转表示、时间戳单位等）
- 任务与传感器概览

## 十、快速上手指南

### 10.1 典型工作流

```
1. 导入数据
   → 打开"导入 dataset"标签页
   → 拖拽上传或选择服务器路径
   → 选择格式（或自动检测）
   → 点击"导入 dataset"

2. 配置过滤器（可选）
   → 展开权重滑块调整各阶段权重
   → 在"VLM 设置"中配置视觉评估

3. 运行清洗
   → 点击"运行清洗 Pipeline"
   → 等待进度条完成

4. 审查结果
   → 查看质量分布图和评分
   → 展开"待审查"分组逐条检查
   → 使用"通过"/"排除"按钮人工判定

5. 3D 回放验证（可选）
   → 选中可疑 Episode
   → 点击"Replay in Rerun"

6. 导出干净数据
   → 选择导出格式和范围
   → 点击"导出干净数据集"
```

### 10.2 数据目录建议

为安全起见，建议将数据集存放在项目代码目录之外：

```bash
~/rslstudio-data/datasets/    ← 数据集存放位置
~/rslstudio-data/rds-artifacts/ ← 导出/回放产物
```

通过 `.env` 文件中的 `RDS_SAMPLES_DIR` 和 `RDS_ARTIFACT_DIR` 配置。
